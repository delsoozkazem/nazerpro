
```bash
cd nazerpro-backend
node src/seed.js       # ساخت دیتابیس + داده نمونه (۳ پروژه، کاربران، چک‌لیست‌ها)
node src/server.js     # اجرای سرور روی پورت 4000
```

سپس مرورگر را باز کنید: **http://localhost:4000**

صفحه ورود نمایش داده می‌شود. یا با فرم وارد شوید یا از لیست «کاربران نمونه» روی صفحه ورود
با یک کلیک وارد شوید (مثلاً «مهندس رضایی» برای دیدن نمای ناظر عمران).

فرانت‌اند (`public/index.html`) توسط همین سرور Node سرو می‌شود — نیازی به سرور جداگانه،
Webpack، یا build step نیست؛ یک فایل HTML خام با JavaScript خالص است که مستقیماً با
`fetch` به `/api/...` وصل می‌شود.

## چرا بدون npm install اجرا می‌شود؟

این بک‌اند **عمداً بدون هیچ وابستگی خارجی (npm dependency)** نوشته شده است و فقط از
ماژول‌های داخلی Node.js استفاده می‌کند:

| نیاز | راه‌حل معمول | جایگزین استفاده‌شده اینجا |
|---|---|---|
| وب‌سرور / روتینگ | Express / NestJS | `node:http` + روتر سبک داخلی (`src/router.js`) |
| دیتابیس | PostgreSQL + Prisma/TypeORM | `node:sqlite` (تجربی، از Node 22.5 به بعد) |
| احراز هویت | jsonwebtoken, bcrypt | پیاده‌سازی سبک JWT (HS256) و هش رمز با `crypto.scrypt` |
| آپلود فایل | multer | دریافت تصویر به‌صورت Base64 (`FileReader` در مرورگر) + ذخیره در `uploads/` |
| فرانت‌اند | React + Vite + build step | HTML/CSS/JS خالص، بدون کامپایل، سرو شده توسط همان Node server |

نتیجه: کل سیستم (بک‌اند + فرانت‌اند + دیتابیس) با یک دستور (`node src/server.js`) و بدون
هیچ نصب بسته‌ای اجرا می‌شود و می‌تواند در هر محیطی (حتی بدون دسترسی اینترنت) تست شود.

**مسیر استقرار واقعی (Production):** برای مقیاس واقعی، مطابق سند طراحی اولیه (بخش ۴۸)،
باید به PostgreSQL مهاجرت کرد و فرانت‌اند را با React/TypeScript بازنویسی کرد. شمای معادل
دیتابیس در `prisma/schema.prisma` و `docs/schema.postgres.sql` آماده است — به بخش
«مهاجرت به PostgreSQL» در پایین همین فایل مراجعه کنید.

## تست سریع جریان کامل (Smoke Test)

اسکریپت `scripts/smoke-test.py` کل جریان اصلی سیستم را روی سرور در حال اجرا تست می‌کند:
ورود → دریافت پروژه‌ها → دریافت چک‌لیست → ثبت بازدید کامل با تصویر و ایراد →
محاسبه امتیاز انطباق → گزارش خودکار → گردش‌کار ایراد → آپلود تصویر → آنالیتیکس → Audit Log.

```bash
node src/server.js &      # سرور را در پس‌زمینه اجرا کنید
python3 scripts/smoke-test.py
```

## معماری امنیتی

- **JWT دو لایه**: Access Token (۱۵ دقیقه) + Refresh Token (۳۰ روز، در جدول `refresh_tokens`
  با قابلیت ابطال/Revoke ذخیره می‌شود).
- **RBAC**: چهار نقش `ADMIN` / `SUPERVISOR` / `CONTRACTOR` / `OWNER`. دسترسی به هر پروژه از طریق
  جدول `project_supervisors` (تخصیص ناظر به تفکیک رشته) یا فیلد `owner_id`/`contractor_id`
  در سطح Query کنترل می‌شود — نه فقط در Middleware سطحی.
- **اعتبارسنجی سرور-محور**: الزام «عکس اجباری» و «توضیح اجباری در صورت رد» در
  `POST /api/visits` مجدداً روی سرور بررسی می‌شود؛ اعتماد صرف به اعتبارسنجی فرانت‌اند کافی نیست.
- **Audit Log**: تمام عملیات حساس (ایجاد/ویرایش/تغییر وضعیت) با کاربر، زمان، مقدار قبل/بعد
  در جدول `audit_logs` ثبت می‌شود (بخش ۴۷ سند طراحی).
- **جلوگیری از جعل مقرراتی (بخش ۱ و ۵۹)**: هر آیتم چک‌لیست دارای پرچم `regulation_verified`
  است. اگر مدیر هنگام تعریف آیتم استناد را «تأییدشده» علامت نزند، سیستم به‌طور خودکار
  `regulation_note = "نیازمند بررسی منبع"` را ثبت می‌کند — هیچ شماره بند یا مقدار فنی
  به‌صورت پیش‌فرض جعل نمی‌شود.
- **گزارش‌های غیرقابل‌تغییر (Immutable Snapshot)**: هر گزارش هنگام صدور، یک snapshot کامل
  JSON از چک‌لیست/آیتم‌ها/امتیاز در لحظه ثبت می‌کند (`reports.content_json`) تا نسخه‌بندی
  بعدی چک‌لیست، گزارش‌های قدیمی را تغییر ندهد (بخش ۵۱).

## محدودیت‌های شناخته‌شده این پروتوتایپ

- تولید PDF واقعی پیاده‌سازی نشده؛ Endpoint گزارش، JSON کامل بازمی‌گرداند که فرانت‌اند
  می‌تواند آن را رندر/چاپ کند (مشابه صفحه گزارش در پروتوتایپ فرانت‌اند).
- ذخیره فایل تصویر روی دیسک محلی است؛ برای Production باید با یک Storage Adapter به
  Cloudflare R2 / S3 / Supabase Storage وصل شود (طبق بخش ۴۸ سند طراحی).
- واترمارک تصویر فقط به‌صورت متادیتا (`watermark_project`, `watermark_date`,
  `watermark_inspection_id`) ذخیره می‌شود؛ رندر واقعی روی پیکسل تصویر نیازمند یک کتابخانه
  پردازش تصویر است.
- Offline Sync (بخش ۴۵) در این نسخه از بک‌اند پیاده نشده — این قابلیت باید در لایه
  فرانت‌اند (IndexedDB) به همراه یک Endpoint «Bulk Sync» در بک‌اند اضافه شود.

## مهاجرت به PostgreSQL

۱. `docker-compose.yml` (نمونه) یک سرویس Postgres بالا می‌آورد.
۲. `docs/schema.postgres.sql` را روی آن اجرا کنید (یا با Prisma: `npx prisma migrate dev`
   با استفاده از `prisma/schema.prisma`).
۳. در `src/db.js`، `DatabaseSync` را با یک کلاینت `pg` (یا Prisma Client) جایگزین کنید؛
